\begin{abstract}
% The template warns against special characters, symbols or math here, so this
% paragraph is deliberately plain prose: no math, no symbols, no figures.
Clustering has been proposed as an alternative to attention and convolution for
mixing visual tokens, and it performs competitively at the model sizes and
input resolutions where it was introduced. Whether it survives compression is a
separate question. Lightweight classifiers deployed at the edge are usually
constrained by the memory their weights occupy rather than by the arithmetic
the processor can retire, and at a few million parameters with small inputs
each clustering stage sees few points to group. We test the mechanism directly
in that regime. Starting from a hybrid block whose token mixer splits channels
between a clustering branch and a local convolutional branch, we vary one
design decision at a time under a matched training budget, repeat every
configuration over several seeds, and compare with paired significance tests
rather than single runs. Clustering does not pay for itself here. Removing the
local branch while holding the stem, fold partitioning, depth and width fixed
costs accuracy; removing the clustering branch instead improves it, at fewer
parameters. The machinery built around clustering contributes less than
run-to-run variation, and the one setting that matters greatly turns out to
matter because of input resolution rather than because of grouping. A
hand-designed sparse local filter is likewise matched by a plain learned
convolution at equal parameters, while costing considerably more activation
memory. Carrying these findings through yields a clustering-free design that,
at the parameter budget of a strong lightweight baseline, exceeds both that
baseline and the larger network used to distil it, on two datasets. The gain
holds under distillation and is paid for in arithmetic, and we report measured
memory and latency on real hardware alongside parameter counts, showing that
operation counts are a poor predictor of measured speed for models of this
kind. We release every configuration, seed and per-image prediction behind the
results.
\end{abstract}
